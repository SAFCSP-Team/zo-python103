# Exception Handling

Exceptions are Python's way of signaling errors or unexpected conditions that occur during program execution. 

When an exception occurs:
1. Python halts the program.
2. It creates an exception object containing details about the error.

This process is called **raising an exception**. If the exception is not handled, Python terminates the program and displays an error message.


### Why Exceptions Occur

Exceptions can arise from various scenarios such as:
- Invalid inputs:
  ```python
  int("abc")  # Raises ValueError
  ```
  
- Division by zero:
  ```python
  1 / 0  # Raises ZeroDivisionError
  ```
  
- File operations:
  ```python
  open("nonexistent.txt")  # Raises FileNotFoundError
  ```

**Example**
```python
import math

x = float(input("Enter x: "))
y = math.sqrt(x)  # Raises ValueError if x is negative

print(f"The square root of {x} is {y}.")
```

Expected output
```
Enter x: -1
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    y = math.sqrt(x)
ValueError: math domain error
```

Python's built-in exceptions follow a structured hierarchy, which aids in organizing exception handling more effectively.

## Handling Exceptions: `try` and `except` Blocks


To prevent program termination, you can handle exceptions using the `try` and `except` keywords.

**Syntax**
```python
try:
    # Code that may raise an exception
except SpecificExceptionName:
    # Code to execute if the exception occurs
```

**Example**
```python
try:
    x = int(input("Enter numerator: "))
    y = int(input("Enter denominator: "))
    print(x / y)
except ZeroDivisionError:
    print("Error: Division by zero is not allowed.")
```

**Output**
```
Enter numerator: 5
Enter denominator: 0
Error: Division by zero is not allowed.
```

### Generic `except`
A generic `except` block catches any exception that occurs inside the corresponding `try` block.

You can write a generic except in two ways:
- `except`: it catches all exceptions. This form is not recommended because it can also catch exceptions such as `KeyboardInterrupt` and `SystemExit`, making it harder to stop a program or diagnose problems.
- `except Exception`: it catches almost all runtime exceptions and is generally preferred if you need a broad exception handler.


Although this can prevent a program from crashing, it is generally **better to catch specific exceptions** whenever possible. Catching only the exceptions you expect makes your code easier to understand, debug, and maintain. A generic except can accidentally hide unexpected bugs.

>[!NOTE]
> Using `except Exception:` is generally preferred over `except:` because it catches most runtime errors while avoiding exceptions such as `KeyboardInterrupt` and `SystemExit`, which are usually intended to stop the program.

**Examples**
```python
try:
    print(1 / 0)
except:
    print("An error occurred.")
```

```python
first_number = int(input("Enter the first number: "))
second_number = int(input("Enter the second number: "))

try:
    print(first_number / second_number)
except Exception: 
    print("An unexpected error occurred.")

print("THE END.")
```


## Handling Multiple Exceptions

### Multiple `except` Blocks

You can handle more than one exception coming from the same `try` block by adding multiple `except` blocks. You should consider the following:

- Python executes the first except block that matches the raised exception and skips the remaining except blocks.
- If an unnamed (general) except block exists, it has to be specified as the last.
- You cannot add more than one unnamed except block.

**Example**
```python
try:
    num = int(input("Enter a number: "))
    res = 1 / num
except ValueError:
    print("Invalid input: Please enter an integer.")
except ZeroDivisionError:
    print("Cannot divide by zero.")
```

### Duplicate `except` Blocks 
If you write identical `except` clauses, Python reads them from top to bottom. It will always execute the first one and completely ignore the second one.

**Example**
```python
try:
    x = 1 / 0
except ZeroDivisionError:
    print("This runs first.")  # Python stops here
except ZeroDivisionError:
    print("This will never run")
```


### Multiple Exceptions in one Block
You can group exceptions together.

**Example**
```python
try:
    num_list = [10, 20, 0, 'thirty']
    for num in num_list:
        result = 100 / num
except (ZeroDivisionError, TypeError):
    print("Error: Division by zero or invalid type detected.")
```

>[!important]
> - The matching branch doesn't have to specify the same exception exactly - it's enough that the exception is more general than the raised one.
> - The order of the blocks matters. Don't put more general exceptions before more concrete ones; this will make the latter one unreachable and useless.



## The `else` and `finally` Blocks

### `else` Block

The `else` block executes if no exceptions occur:

**Example**
```python
try:
    x = 10 / 2
except ZeroDivisionError:
    print("Division error.")
else:
    print("Success:", x)
```

**Output**
```
Success: 5.0
```

### `finally` Block
The `finally` block **always executes**, whether an exception occurs or not. It is ideal for clean-up actions.

**Example**
```python
try:
    f = open("file.txt", "r")
    data = f.read()
except FileNotFoundError:
    print("File not found.")
finally:
    print("Execution complete.")
```


## Raising Exceptions

### Manually Raising Exceptions
The `raise` keyword is used to raise exceptions or errors during program execution. When you raise an exception using raise, you specify the type of exception to be raised and, optionally, a message that provides more information about the error.

**Example**
- Raise a `ValueError` :
```python
x = -5
if x < 0:
    raise ValueError
```
**Output**
```
Traceback (most recent call last):
  File "<main.py>", line 3, in <module>
ValueError
```

- Raise a `ValueError` with a custom message:
```python
x = -5
if x < 0:
    raise ValueError("x should be a positive number")
```


### Re-Raising Exceptions in `except`
In an `except` block, use `raise`  without arguments to pass the exception up for further handling:

**Example**
```python
def bad_fun(n):
    try:
        return n / 0
    except:
        print("I did it again!")
        raise

try:
    bad_fun(9)
except ArithmeticError:
    print("I see!")
```

**Output**
```
I did it again!
I see!
```


## Accessing Exception Details: `as` keyword
The `as` keyword is used to assign the caught exception to a variable. This variable allows you to access information about the exception that was raised. You can then use this variable to handle the exception or extract specific details about the error.

**Example**
```python
try:
    numbers = [1, 2, 3]
    index = 3
    raise IndexError("Index out of range:", index)
except IndexError as e:
    print("IndexError Message:", e)
    print("Arguments Passed with Exception:", e.args)
```

**Output**
```
IndexError Message: ('Index out of range:', 3)
Arguments Passed with Exception: ('Index out of range:', 3)
```


## User-Defined Exceptions

Creating custom exceptions helps in handling application-specific errors:

### Steps to Create and Use User-Defined Exceptions
1. **Define a New Exception Class**: Create a new class that inherits from Exception or any of its subclasses.
2. **Raise the Exception**: Use the raise statement to raise the user-defined exception when a specific condition occurs.
3. **Handle the Exception**: Use try-except blocks to handle the user-defined exception.


**Example**
```python
# Step 1: Subclass of the Exception Class
class InvalidAgeError(Exception):
    def __init__(self, age, msg="Age must be between 0 and 120", error_code=1001):
        # Custom attributes
        self.age = age
        self.msg = msg
        self.error_code = error_code
        super().__init__(self.msg)  # Call the base class constructor

    def __str__(self):
        return f"[Error Code {self.error_code}] {self.age} -> {self.msg}"

# Step 2: Raising the custom exception
def set_age(age):
    if age < 0 or age > 120:
        raise InvalidAgeError(age)
    else:
        print(f"Age set to: {age}")


# Step 3: Handling the custom exception 
try:
    set_age(150)  # This will raise the custom exception
except InvalidAgeError as e:
    print(e)
```

**Output**
```
[Error Code 1001] 150 -> Age must be between 0 and 120
```



## Common Built-in Exceptions

| Exception           | Description                                                   |
|--------------------------|----------------------------------------------------------|
| TypeError            | Raised for type mismatches                                   |
| ValueError           | Raised for invalid values of the correct type                |
| KeyError             | Raised for missing dictionary keys                           |
| ZeroDivisionError    | Raised when dividing by zero                                 |
| FileNotFoundError    | Raised for missing file operations                           |
| MemoryError          | Raised when Python runs out of usable memory                 |
