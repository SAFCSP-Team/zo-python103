# Exception Handling

Exceptions are Python's way of signaling errors or unexpected conditions that occur during program execution. 

When an exception occurs:
1. Python halts the program.
2. It creates an exception object containing details about the error.

This process is called **raising an exception**. If the exception is not handled, Python terminates the program and displays an error message.


### Why Exceptions Occur

Exceptions can arise from various scenarios such as:
- Invalid inputs:
  ```python
  int("abc")  # Raises ValueError
  ```
  
- Division by zero:
  ```python
  1 / 0  # Raises ZeroDivisionError
  ```
  
- File operations:
  ```python
  open("nonexistent.txt")  # Raises FileNotFoundError
  ```

Example

```python
import math

x = float(input("Enter x: "))
y = math.sqrt(x)  # Raises ValueError if x is negative

print(f"The square root of {x} is {y}.")
```

Expected output
```
Enter x: -1
Traceback (most recent call last):
  File "main.py", line 4, in <module>
    y = math.sqrt(x)
ValueError: math domain error
```

## Exception Hierarchy

Python's built-in exceptions follow a structured hierarchy, which aids in organizing exception handling more effectively.

- Every exception inherits from `BaseException`.
- The Exception class is the parent for most user-defined and built-in errors.
- More specific exceptions subclass general ones (e.g., `ZeroDivisionError` is a subclass of `ArithmeticError`).

### The `try` and `except` Block: Handling Exceptions


To prevent program termination, you can handle exceptions using the `try` and `except` keywords.

Syntax
```python
try:
    # Code that may raise an exception
except SpecificExceptionName:
    # Code to execute if the exception occurs
```

Example
```python
try:
    x = int(input("Enter numerator: "))
    y = int(input("Enter denominator: "))
    print(x / y)
except ZeroDivisionError:
    print("Error: Division by zero is not allowed.")
```

Output
```
Enter numerator: 5
Enter denominator: 0
Error: Division by zero is not allowed.
```

### Generic `except`

A generic `except` block catches any exception. If you use an except without an exception name, it will catch all exceptions, but it's best practice to catch specific exceptions when possible to avoid hiding unexpected bugs.

```python
try:
    print(1 / 0)
except:
    print("An error occurred.")
```

Example
```python
first_number = int(input("Enter the first number: "))
second_number = int(input("Enter the second number: "))

try:
    print(first_number / second_number)
except Exception: # handles any exception
    print("An unexpected error occurred.")

print("THE END.")
```


### Handling Multiple Exceptions

#### 1. With Multiple `except` Blocks

You can handle different exceptions based on their types and you should consider the following:

- You must not use more than one except block with a certain exception name.
- The first matching except block will execute, so the other blocks will not be visited.
- If an unnamed (general) except block exists, it has to be specified as the last.
- You cannot add more than one unnamed except.

```python
try:
    num = int(input("Enter a number: "))
    res = 1 / num
except ValueError:
    print("Invalid input: Please enter an integer.")
except ZeroDivisionError:
    print("Cannot divide by zero.")
```

#### 2. Multiple Exceptions in one Block
You can group exceptions together:
```python
try:
    num_list = [10, 20, 0, 'thirty']
    for num in num_list:
        result = 100 / num
except (ZeroDivisionError, TypeError):
    print("Error: Division by zero or invalid type detected.")
```

### The `else` and `finally` Blocks

#### 1. `else` Block

The `else` block executes if no exceptions occur:
```python
try:
    x = 10 / 2
except ZeroDivisionError:
    print("Division error.")
else:
    print("Success:", x)
```

Output
```
Success: 5.0
```

#### 2. `finally` Block
The `finally` block **always executes**, whether an exception occurs or not. It is ideal for clean-up actions.
```python
try:
    f = open("file.txt", "r")
    data = f.read()
except FileNotFoundError:
    print("File not found.")
finally:
    print("Execution complete.")
```

>[!important]
> - The matching branch doesn't have to specify the same exception exactly - it's enough that the exception is more general (more abstract) than the raised one.
>- The order of the blocks matters.
>- Don't put more general exceptions before more concrete ones; this will make the latter one unreachable and useless.


### Raising Exceptions

#### Manually Raising Exceptions
You can explicitly raise exceptions using the `raise` keyword:
```python
x = -5
if x < 0:
    raise ValueError("x must be non-negative.")
```

#### Re-Raising Exceptions in `except`
In an `except` block, use `raise` to pass the exception up for further handling:
```python
try:
    x = 1 / 0
except ZeroDivisionError:
    print("Error caught.")
    raise
```


### User-Defined Exceptions

Creating custom exceptions helps in handling application-specific errors:
```python
class CustomError(Exception):
    pass

try:
    raise CustomError("This is a custom exception.")
except CustomError as e:
    print(e)
```


### Accessing Exception Details `as`

The `as` keyword allows you to retrieve information about exceptions:

```python
try:
    x = 1 / 0
except ZeroDivisionError as e:
    print(f"Exception occurred: {e}")
```

### Common Built-in Exceptions

| Exception           | Description                                                   |
|--------------------------|----------------------------------------------------------|
| TypeError            | Raised for type mismatches                                   |
| ValueError           | Raised for invalid values of the correct type                |
| KeyError             | Raised for missing dictionary keys                           |
| ZeroDivisionError    | Raised when dividing by zero                                 |
| FileNotFoundError    | Raised for missing file operations                           |
| MemoryError          | Raised when Python runs out of usable memory                 |

>[!note]
>For the full list, visit [Python Built-In Exceptions](https://docs.python.org/3/library/exceptions.html).
