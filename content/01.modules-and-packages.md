# Modules and Packages
As Python programs grow larger, keeping all your code in a single file becomes difficult. Large files are harder to read, debug, test, and maintain. Python solves this problem using **modules** and **packages**, which allow you to divide a program into smaller, reusable, and well-organized components.


Using modules and packages makes programs:
- Easier to organize
- Easier to understand
- Easier to maintain
- Easier to reuse across multiple projects


## What is a Module? 
A **module** is a single Python file (`.py`) containing definitions and executable statements (such as functions, classes, variables, and constants) that can be imported and used in other Python files.

A module has a unique name (it's the filename without the `.py` extension) and can be imported into other Python programs.

**Example**

Suppose you have a file named `calculator.py`.

```python
def add(a, b):
    return a + b

def subtract(a, b):
    return a - b

PI = 3.14159
```
The entire file is a module named `calculator`.

Modules allow you to write code once and reuse it in many different programs. You can import this module into another Python program and reuse its contents instead of rewriting the same code.


## Importing a Module
To use a module, import it using the `import` keyword followed by the module name.

**Example**
```python
import math
```
- `import` is a keyword used to include a module.
- `math` is the module name.

After importing a module, its entities are accessed using **dot notation**.

```python
module_name.entity_name
```

**Example**
```python
import math

print(math.sqrt(25))
```

> [!IMPORTANT]
> A module must be imported before any module entities are used.


### Importing Multiple Modules
By convention, import statements are placed near the beginning of a Python file. You can import multiple modules using separate statements.

**Example**
```python
import math
import sys
import random
```
Alternatively, they can be imported in a single statement.

```python
import math, sys, random
```

Although both approaches are valid, separate import statements are generally preferred because they are easier to read and maintain.


### Importing Specific Entities
You can import specific entities from a module, such as a function, class, or variable.

**Example** 
```python
from math import sin, pi

print(sin(pi / 2))
```
Since `sin` and `pi` are imported directly into the current namespace, you can use them without mentioning the module name `math.`.


### Importing All Entities
You can import every public entity from a module into the current namespace, using the `*` symbol.

**Example** 
```python
from math import *
```


## Aliasing
Sometimes module or entity names are long or may conflict with existing names. Python allows you to import them under different names using the `as` keyword.

### Aliasing a module
```python
import random as r

print(r.random())
```
`random` is referenced using the shorter alias `r`.


### Aliasing specific entities
```python
from math import pi as PI
from math import sin as sine

# OR
# from math import pi as PI, sin as sine

print(sine(PI / 2))
```
This imports:
- `pi` as `PI`
- `sin` as `sine`

> [!NOTE]
> After importing a module or entity using an alias, the original module name is **not** available in the current namespace.


## Namespaces
Every Python module has its own **namespace**, which is a collection of names (such as variables, functions, and classes) that belong to a particular scope. This means two different modules can define variables or functions with the same name.

**Example**  
```python
import math

def sin(x):
    return "My custom sin function"

print(sin(1))
print(math.sin(1))
```
- `sin()`: refers to your own function.
- `math.sin()`: refers to the function inside the math module.


Both your program and the `math` module can define a function named `sin`, but each module has its own namespace, the two functions do not interfere with one another.


### Importing into the Current Namespace

When you import a module, its entities don’t enter your script’s namespace unless you use `from module import ...`.

**Example**  
```python
from math import sin

print(sin(1))
```
`sin` is imported directly into the current namespace. This means you can call it without writing `math.sin()`. However, importing names directly increases the chance of conflicts if your program defines another function or variable with the same name.

For this reason, many Python programmers prefer:

```python
import math

math.sin(1)
```

Because it clearly indicates where the function comes from.


## The `__name__` Variable

Every Python module contains a built-in variable named ` __name__`. Its value depends on how the module is used:

- When a module is executed directly, `__name__`is set to `"__main__"`.
- When a module is imported into another program,` __name__ `is set to the module's name.

This allows a module to behave differently depending on whether it is run as a program or imported as a library.

**Example**
```python
# mymodule.py
def hello():
    print("Hello!")

if __name__ == "__main__":
    hello()   # Only runs when executed directly, not when imported
```

## The `__pycache__` Directory

When Python imports a module, it compiles the source code into **bytecode**. The compiled bytecode is stored in the `__pycache__` directory.

**Example**
```text
project/
│
├── mymodule.py
│
└── __pycache__/
    └── mymodule.cpython-xyz.pyc
```

The filename contains:
- The module name
- The Python implementation
- The Python version


When Python imports a module, it may reuse cached bytecode instead of recompiling the source code, making imports faster. You typically do **not** need to manually manage the files in the `__pycache__` directory.


## The `dir()` Function
The built-in `dir()` function returns an alphabetically sorted list containing all the entities' names available in the module. This is useful when exploring unfamiliar modules.

**Example**
```python
import math
print(dir(math))
```

**Output**
```text
['acos', 'asin', 'atan', 'ceil', 'cos', 'factorial', 'floor', 'pi', 'sqrt', ...]
```

The list includes the names of functions, constants, classes, and other attributes defined by the module. You can also use `dir()` without an argument to display the names currently available in the current namespace.

**Example**
```python
x = 10

def square(n):
    return n * n

print(dir())
```


## Python Standard Library

Python includes a large collection of built-in modules known as the **Python Standard Library**. These modules provide ready-to-use functionality for many common programming tasks and are available without installing additional software.

Some commonly used standard library modules include:

| Module        | Purpose                        |
| ------------- | ------------------------------ |
| `math`        | Mathematical functions         |
| `random`      | Pseudo-random number generation|
| `os`          | Operating system interaction   |
| `sys`         | Python interpreter information |
| `datetime`    | Working with dates and times   |
| `json`        | JSON encoding and decoding     |
| `pathlib`     | Object-oriented file paths     |
| `re`          | Regular expressions            |

**Example**

The `math` module provides mathematical constants and functions commonly used in scientific and numerical calculations.

```python
from math import pi, sqrt, floor, ceil, log

x = 2.6

print(pi)
print(sqrt(x))
print(floor(x))
print(ceil(x))
print(log(x))
```


## What is a Package?
As projects grow larger, a single module is often no longer enough to organize all the code. Related modules can be grouped into **packages**, making large applications easier to structure and maintain.

A **package** is a collection of related modules organized into directories. It helps keep related code together and prevents large projects from becoming difficult to navigate.

A package is a directory containing:
- An `__init__.py` file (which may be empty or contain initialization code)
- One or more module files
- Optionally, one or more subpackages


> [!NOTE]
> A package can be a directory tree or even a zipped archive.


**Example**
```text
my_package/
│
├── __init__.py
├── math_utils/
├── geometry.py
└── statistics.py
```


A package may also contain subpackages:

```text
my_package/
│
├── __init__.py
├── math_utils.py
│
└── graphics/
    ├── __init__.py
    ├── shapes.py
    └── colors.py
```
`graphics` is a **subpackage** because it is itself a package contained within another package.


## The `__init__.py` File

The `__init__.py` file is a special file placed inside a directory that indicates it is a Python package.

Its purposes include:
- Marking a directory as a package (required in older Python versions)
- Running package initialization code
- Defining the package's public interface
- Importing commonly used modules automatically


The code inside `__init__.py` is executed when any module in the package is imported.  If no initialization is required, the file can be empty.


> [!NOTE]
> Since Python 3.3, packages can also be **namespace packages**, which do not require an `__init__.py` file. However, many projects still include `__init__.py` because it improves clarity and allows package initialization.


## Importing from Packages
Suppose the project has the following structure:

```text
project/
│
├── main.py
│
└── my_package/
    ├── __init__.py
    └── math_utils.py
```

Contents of `math_utils.py`:

```python
def square(x):
    return x * x
```

#### Importing an Entire Module

```python
from my_package import math_utils

print(math_utils.square(5))
```

#### Importing Specific Entities

```python
from my_package.math_utils import square

print(square(5))
```

Both approaches are valid. Importing the entire module clearly indicates where a function comes from, while importing individual entities can make code shorter when only a few names are needed.


## The `pip` Package Manager
The Python Standard Library includes many useful modules, but the Python community develops thousands of additional packages. These packages are distributed through the **Python Package Index (PyPI)** and are typically installed using `pip`, Python's package manager.

Although the command `pip` is widely used, many developers prefer using:

```bash
python -m pip
```
This ensures that `pip` is linked with the correct Python interpreter, which is especially helpful when multiple Python versions are installed.


#### Installing a Package
```bash
python -m pip install requests
```
Or 
```bash
pip install requests
```

#### Upgrading a Package
```bash
python -m pip install --upgrade requests
```

#### Uninstalling a Package
```bash
python -m pip uninstall requests
```

#### Listing Installed Packages
```bash
python -m pip list
```

#### Viewing Package Information
```bash
python -m pip show requests
```

## Module and Package Perspectives

When working with modules and packages, you can take one of two perspectives:

1. A **module or package user** imports existing modules or packages to add functionality to your application. These modules may be:
- Part of the Python Standard Library
- Developed by your team or organization
- Installed from third-party packages

2. A **module or package author** creates reusable modules and packages for others to use. These may be designed for:
- Personal projects
- Internal company use
- Open-source distribution
- Commercial software


## Creating Your Own Modules and Packages
Instead of placing all your code into one file. You can create your own modules and packages by writing code in separate files (modules) and directories (packages) to:

**Example**
```
project/
│
├── main.py
│
└── utilities/
    ├── __init__.py
    ├── calculator.py
    ├── strings.py
    └── files.py
```
Each file is a module that provides related functionality:
- `calculator.py`: contains mathematical functions.
- `strings.py`: contains string utilities.
- `files.py`: contains file-handling functions.
- `main.py` imports and uses the functions provided by these modules.
- The` __init__.py` file tells Python that the `utilities` directory is a package.
