# Abstraction and Interface
Abstraction and interfaces are fundamental concepts in Object-Oriented Programming that help developers create flexible and maintainable software by simplifying complex systems, encouraging code reuse, and establishing consistent behavior across related classes.
## Abstraction
Abstraction is one of the fundamental principles of Object-Oriented Programming(OOP). It refers to the process of hiding implementation details and exposing only essential features or functionality to the user.

In Python, abstraction is achieved through abstract classes and interfaces. These serve as blueprints for creating concrete classes while ensuring a consistent structure.

### Why use Abstraction?
- Simplifies complexity by only focusing on what an object does, not how it does it.
- Improves code modularity and reusability.
- Helps enforce a contract for child classes to follow a predefined structure.


### Abstract Classes
An abstract class in Python is a class that cannot be instantiated. It serves only as a blueprint for its subclasses. Abstract classes are defined using the `ABC` (Abstract Base Class) module.


```python
from abc import ABC, abstractmethod

class Vehicle(ABC):  # Abstract class
    @abstractmethod
    def start_engine(self):
        pass      # Abstract method (no implementation)
```

>[!Important]
>`@abstractmethod`: A decorator that marks a method as abstract. **Subclasses must implement all abstract methods** from the abstract class. </br>

**Example**

```python
from abc import ABC, abstractmethod

class Vehicle(ABC): 
    @abstractmethod
    def start_engine(self):
        pass  # Abstract method must be implemented by subclasses

    def stop_engine(self):  # Concrete method
        print("Engine stopped!")

class Car(Vehicle):  
    def start_engine(self):
        print("Car engine started!")

class Bike(Vehicle): 
    def start_engine(self):
        print("Bike engine started!")

# Instantiate 
car = Car()
car.start_engine()  # Car engine started!
car.stop_engine()   # Engine stopped!

bike = Bike()
bike.start_engine()  # Bike engine started!
bike.stop_engine()   # Engine stopped!
```

>[!note]
> 1. Concrete methods are fully implemented methods within an **abstract class**. Subclasses can inherit and use them directly, promoting code reuse without needing to redefine common functionality.</br>
> 2. The `Vehicle` class is abstract and cannot be instantiated. </br>
> 3. The `stop_engine` method in the `Vehicle` class is a concrete method. It provides a default implementation for stopping the engine.


## Interface

An interface is a concept in OOP that defines a contract of methods that a class must implement. In Python, interfaces can be created using abstract classes with only abstract methods. It ensures the class will have specific methods, but doesn’t enforce how they should be implemented.

Interfaces focus on action/behavior rather than inheritance hierarchies, unlike an abstract class, which typically enforces an is-a relationship.


We can create and implement interfaces in two ways:

- formal interface
- informal interface


### Formal interface
Formal interface in Python are implemented using an abstract base class (`ABC`). To use this class, you need to import it from the `abc` module.

**Example**

```python
from abc import ABC, abstractmethod
class Flyable(ABC):  # Interface showing "can fly" behavior
    @abstractmethod
    def fly(self):
        pass

class Drone(Flyable):  # "Drone can fly"
    def fly(self):
        print("Drone is flying with propellers.")

class Bird(Flyable):  # "Bird can fly"
    def fly(self):
        print("Bird is flying with wings.")

# Create instances of classes implementing the Flyable interface
drone = Drone()
drone.fly()  # Output: Drone is flying with propellers.

bird = Bird()
bird.fly()  # Output: Bird is flying with wings.
```



### Informal interface
In Python, an informal interface refers to a class whose methods are intended to be overridden. However, Python does not enforce that subclasses implement all of these methods.

This type of interface works on the principle of duck typing. It allows us to call any method on an object without checking its type, as long as the method exists.


>[!Note]
> Duck typing is that if an object implements all the expected methods of an interface, its type becomes irrelevant ("If it behaves like a duck, it is a duck.").

**Example**

```python
class DemoInterface:
    def displayMsg(self):
        pass

class NewClass(DemoInterface):
    def displayMsg(self):
        print("This is my message")

class AnotherClass:  # Does not inherit but behaves similarly
    def displayMsg(self):
        print("This is another message")

# Duck typing in action
def show_message(obj):
    obj.displayMsg()

# Objects of both classes "act like" DemoInterface
obj1 = NewClass()
obj2 = AnotherClass()

show_message(obj1)  # Output: This is my message
show_message(obj2)  # Output: This is another message

```


## Differences Between Abstract Class and Interface

| Feature                     | Abstract Class                      | Interface                               |
|-----------------------------|-------------------------------------|----------------------------------------|
| Definition           | Class with both abstract and concrete methods| A contract with only abstract methods|
| Instance Creation       | Cannot be instantiated directly| Cannot be instantiated directly|
| Purpose                 | Establishes an "is-a" relationship |Defines a "can-do" relationship|
| Implementation         | Can have concrete methods| Typically only abstract methods|
